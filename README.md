# Promit

**Buy one prompt for cents. No subscription, no account, no API key — and an AI agent can buy it without you.**

Promit turns any prompt into an [x402](https://x402.org)-payable resource on Base Sepolia. A buyer signs a message, pays USDC, and gets the prompt. So does an autonomous agent.

---

## The claim, and the receipt

Prompt libraries sell $300 lifetime bundles because no payment rail makes a five-cent sale viable — Stripe alone takes ~$0.30 plus 2.9%, six times the price of the good. Micropayments for digital goods died for cost reasons, not demand reasons.

That is easy to assert. Here it is settled on-chain:

| | |
|---|---|
| Transaction | [`0x7b62a3ae…6a85`](https://sepolia.basescan.org/tx/0x7b62a3ae1bd835907f3f4b9541cf9b4b082c687c5267795178ad2e2c5aad6a85) |
| Status | success, block 45141360, settled in **533 ms** |
| Signer (payer) | `0xadE939F26516c657fc01f2eD1B069562b672644c` — holds **0 wei ETH** |
| `tx.from` (gas payer) | `0xd407e409…f1bf` — the facilitator's own signer |

Read the last two rows together. The buyer held **no ETH** and still paid USDC on-chain, because they signed an EIP-3009 authorization rather than sending a transaction, and the facilitator broadcast it.

That is the whole thesis. It is also why agents are the interesting buyer: an agent wallet needs only stablecoin, and there is no account to create or API key to provision.

## Why an agent would buy rather than write its own

Because a paid listing carries a preview generated by **running that exact prompt**. You are paying for verified output, not for text a model could improvise. That claim is the criterion the agent-facing skill reasons from.

## Design decisions worth knowing

**Prompt text never reaches a client before settlement.** The competitor this project studies ships its entire prompt library inside the client bundle and enforces the paywall only in the UI. Promit's catalog splits public metadata from private bodies as separate types, and a paid body in the git-tracked catalog is a schema load error rather than a leak waiting to be found.

**Spend caps pin denomination before amount.** An amount-only cap is defeated by an 18-decimal token whose `amount` looks small against a 6-decimal USDC threshold. A per-prompt cap alone is defeated by repetition. Both are enforced in the shared client, so no surface can drift.

**Purchased text is untrusted data.** Anyone can list a prompt and an agent buys unattended, so the buy tool returns bodies inside a delimited untrusted-content block — never as instructions to follow.

**The registry records; it never custodies.** Payment goes to a plain address. Keeping the contract off the payment path means a contract bug cannot take the payment demo down.

## Getting started

Requires [bun](https://bun.sh) 1.3+, [Foundry](https://getfoundry.sh), and Node 20+.

```bash
bun install
cp .env.example .env          # fill in keys; PAY_TO_ADDRESS must be an EOA

cd smartcontract && forge clean && forge test    # 22 tests
cd ../backend    && bun test                     # 45 tests
cd ../frontend   && bun run dev
```

To reproduce the settlement proof, fund a wallet with Base Sepolia USDC at [faucet.circle.com](https://faucet.circle.com) — no ETH needed — then:

```bash
bun run scripts/spike-facilitator.ts
```

## Notes on the ecosystem

Two things will waste your time if you follow current tutorials:

- **x402 is on v2.** The unscoped `x402-*` packages are deprecated; use `@x402/*`. Headers, network strings, and the amount field all changed, and only v2 supports per-resource dynamic pricing.
- **The facilitator URL in the official v2 READMEs does not resolve.** `facilitator.x402.org` is NXDOMAIN. Use `https://x402.org/facilitator`.

More in [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).
